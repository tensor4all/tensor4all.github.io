tensor4all

Tensor networks, and the Rust stack for computational physics underneath them

We are an open research community working on tensor cross interpolation, quantics tensor trains and tree tensor networks. To run them we build a layered Rust stack, from strided kernels and batched linear algebra up to a tensor runtime with autodiff, that any computational physics code can use.

A Rust stack for computational physics New

It started as the engine for our tensor network algorithms. It has grown into general infrastructure: each layer is a separate library you can adopt on its own, whether you need fast tensor contraction, batched linear algebra or automatic differentiation over Fortran friendly layouts.

tensor runtime

tenferro-rs

Dense tensors with einsum, linear algebra and FFT on CPU, CUDA and XLA backends, plus eager and traced automatic differentiation (VJP, JVP, higher order). Column major, with explicit device and thread control. crates.io 0.7.1

building blocks

Kernels you can use without tenferro

  • strided-rs: strided views and permutation kernels
  • tcontract: binary contraction over arbitrary strides, with a C ABI
  • tlinalg: batched SVD, QR, LU, Cholesky and eigensolvers
  • cpueinsum: N-ary einsum with a caller supplied order
  • hataori: map and pmap over Rayon and MPI
algorithms

tensor4all-rs

TCI, quantics tensor trains, Fourier and shift operators, tree tensor networks and patching, with a C API and the Tensor4all.jl frontend. active development

Documentation →

Not only for tensor networks

The kernels know nothing about tensor networks: they take plain strided views and an explicit context, and tcontract exposes a C ABI, so existing C, C++ and Fortran codes can call them directly.

Explicit by design

No hidden global thread pools and no behavior switched by environment variables. The caller passes a context down, so an MPI program, a Julia session and a Rust test can share one machine predictably.

Measured in the open

Reproducible CPU and GPU comparisons against PyTorch and JAX live in tenferro-benchmark, keyed by commit and hardware.
